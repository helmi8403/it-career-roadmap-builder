Chapter 2 · AZ-305

02 | Observability, logging and security operations

Official Azure reference diagrams·Study guide prepared October 2026

Exam mapping: Identity, governance and monitoring (25–30%)

Architect monitoring by starting with the signal and the response: metrics and resource health for platform behavior, resource logs for detailed operations, application telemetry for user experience and dependencies, and security products for threat findings.

Data types

Azure Activity Log captures subscription control-plane events; resource logs capture service-specific operations through diagnostic settings; Azure Monitor metrics capture numeric time-series values; Log Analytics stores searchable logs; Application Insights provides application performance and user telemetry.

Routing and retention

Send diagnostic logs to Log Analytics for KQL investigations, Event Hubs for downstream SIEM integration or Storage for long-term archive. Match retention, ingestion volume, latency and compliance needs.

Alerts and response

Metric alerts suit thresholded telemetry and can be low latency. Log alerts support complex KQL. Action groups route notifications and trigger automation. Service Health is distinct from Resource Health.

Private monitoring

Azure Monitor Private Link Scope can restrict telemetry ingestion/query paths where supported; confirm DNS, network egress and managed endpoint service compatibility.

Observability SLOs

Define measurable SLI/SLO indicators: request success rate, latency percentiles, dependency failure rate, data freshness and recovery health. Alert on user-impacting symptoms before infrastructure noise.

Service-choice matrix

Need Service / feature Decision reason
Monthly report of deployment events Activity Log + export/query Control-plane deployment events
External SIEM pipeline Diagnostic settings → Event Hubs Stream platform/resource logs to consumer
Web UX, availability and dependency tracing Application Insights Application-layer instrumentation
Cheap long-term audit archive Storage account via diagnostic settings Retention and immutable storage when required
Advanced KQL cross-resource detection Log Analytics workspace Schema and retention cost design

Exam traps and design warnings

  • Activity Log is not a replacement for all data-plane auditing.

  • Metrics and logs have different cost/retention/query characteristics.

  • Never infer that enabling diagnostic settings automatically configures security alert rules.

Guided lab: End-to-end telemetry pipeline

  1. Create a minimal test resource and Log Analytics workspace with a bounded budget.

  2. Route a supported diagnostic category to Log Analytics; run a KQL query that filters by OperationName or ResourceId.

  3. Define a metric alert with an action group and a simple runbook response outline.

  4. Draft a retention matrix: 30-day operational search, 1-year audit access, 5-year archive. Explain costs and controls.

Evidence to retain: one diagram, one option-comparison table, a short ADR, a verification screenshot/command result (where actually implemented), and a teardown/cost note.
